# Постройка: пакеты и очередь апгрейдов

Два механизма, общие для всех построек: **пакет уровней** (купить сразу 5 или 10
уровней одним действием — и при постройке нового здания, и при апгрейде) и **очередь
апгрейдов** (накликать несколько уровней вперёд у построек с таймером).

---

## 1. Пакет уровней (Ctrl / Shift)

Модификатор читается в момент **выбора инструмента** — клик по слоту панели или
цифровая клавиша:

| Модификатор | Уровней за одно действие | Константа |
|---|---|---|
| — | 1 | |
| **Ctrl** (или ⌘) | **5** | `BUILD_BATCH_CTRL` |
| **Shift** | **10** | `BUILD_BATCH_SHIFT` |

Почему при выборе, а не при клике по карте: Shift там уже занят выделением боевых
кораблей и непрерывным сбросом ракет, а Ctrl-клик по своему кораблю переключает
выделение.

**Что происходит.** Одно действие покупает сразу `levels` уровней:

- **новое здание** ставится **сразу нужного уровня** (Ctrl + порт на пустом берегу →
  порт 5 уровня);
- **клик по своему зданию** (или рядом с ним, где это трактуется как апгрейд)
  поднимает его **на столько же уровней**;
- то же и для кнопки апгрейда в контекстном меню здания.

**Цена — сумма шагов лестницы, а не «цена × N».** У порта, города, завода, ПВО и штаба
цена зависит от того, сколько уже построено, и растёт с каждым уровнем:

```ts
batchCost(step, from, count) = Σ step(from + i)   для i = 0…count−1
```

| Действие | Уровней | Списано |
|---|---|---|
| Порт с нуля | 5 | **2 950 000** (200к + 250к + 500к + 1млн + 1млн) |
| Порт 5 → 10 | 5 | 5 000 000 |
| Порт 10 → 20 | 10 | 10 000 000 |

Наивное умножение (`200к × 5 = 1млн`) занижало бы цену втрое, и игрок включал бы
пакет, на который денег нет. У шахты цена плоская (`SILO_COST`), там сумма и
произведение совпадают.

**Проверка денег.** Слот в панели доступен, только если хватает на весь пакет; пока
модификатор зажат, на слотах видны бейдж `×5`/`×10` и суммарная цена. Для города есть
особый случай: вне пакета слот доступен, когда хватает **или** на новый город,
**или** на апгрейд существующего; в пакете апгрейд не при чём.

**Частичный успех — это норма.** Уровни покупаются по одному, поэтому если денег
хватило на три из пяти, купятся три, и ошибки не будет. Ошибка возвращается только
когда не прошёл ни один шаг.

**Сервер считает сам.** Клиент отправляет `levels` в сообщении, но цену и все
ограничения проверяет сервер, по шагу на уровень. Значение режется в `1…10`
(`clampLevels` в `server/net/handlers.ts`) — подделанное сообщение не прокачает здание
на тысячу уровней за тик.

**Доращивание только что поставленного здания.** У свежего здания `readyTick` в
будущем, и обычный апгрейд отвечает «Ещё строится». Для пакета есть флаг
`allowUnbuilt`: он применяется **только** к зданию, созданному этим же действием, чтобы
оплаченные уровни встали сразу. Постройки с таймером апгрейда (ПВО, шахта) при этом
складывают шаги в свою очередь — она достраивается, пока идёт основная стройка.

## 2. Очередь апгрейдов

Постройки, у которых апгрейд занимает время — **ПВО**, **ракетная шахта**, **штаб** —
позволяют накликать уровни вперёд, не дожидаясь каждого.

```ts
export const UPGRADE_QUEUE_MAX = 11; // один в работе + ДЕСЯТЬ в очереди
```

Было `5` (то есть всего `+4` сверх текущего), стало `11` (`+10`).

Оплата считается по **будущему** уровню, с учётом всего, что уже стоит в очереди:
иначе можно было бы накликать пачку по цене первого шага. У ПВО в сумму уровней
добавляется `pendingUpgrades(playerId, 'sam')`.

Порт, город и завод апгрейдятся **мгновенно** — очередь к ним не относится.

У штаба свой потолок `MAX_HQ_LEVEL`, и он срабатывает раньше очереди.

## 3. Где в коде

| Что | Где |
|---|---|
| Константы пакета и `batchCost` | `shared/constants/game.ts` |
| Потолок очереди | `UPGRADE_QUEUE_MAX` там же |
| Очередь на сервере | `server/game/index.ts` → `upgrade`, `pendingUpgrades`, `upQueue` |
| Захват пакета | `client/App.tsx` → `heldBatch`, `buildLevels`, `gc.onBuild` |
| Применение уровней | `server/game/index.ts` → `build`, `upgrade`, `upgradeOnce` |
| Ограничение от подделки | `server/net/handlers.ts` → `clampLevels` |
| Цены пакета в панели | `client/App.tsx` → `batchCostOf` |
